Geographic unit: “Boston neighborhoods” is not a unit you can reliably find data at. Most income, demographic, and even price data is published at the Census tract or block group level, not by informal neighborhood name. This project adopts tract as its working geographic unit — fine-grained enough to show variation within the city, and it's the unit the ACS data is actually published at.

Also reasonable: block group, if you want finer spatial detail and are comfortable with noisier income estimates. ZIP code is usually a weaker choice since ZIP boundaries don't align well with Census demographic data.

Want to actually try this in ArcGIS Pro? Here's real data you can download right now:

  • Property Assessment (Excel/CSV, price data): data.boston.gov/dataset/property-assessment — pick the latest fiscal year CSV
  • Parcels (shapefile, geometry): data.boston.gov/dataset/parcels-2024 — download as Shapefile from the landing page
  • Income & demographic data (ACS tables): data.census.gov — search Table S1903 (income) or DP05 (race/ethnicity), filtered to Census Tract geography in Suffolk County, MA
  • Census tract boundaries (shapefile): census.gov/cgi-bin/geo/shapefiles/index.php — select a year, layer type "Census Tracts," and state Massachusetts

Join fields once everything's loaded: Property Assessment → Parcels via PID/GIS_ID; ACS table → Tract boundaries via GEOID.

Question 3:What data prep will you need?

Looking at the two datasets you just inspected, walk through these three checks to figure out what prep is needed before they could be combined into one map:

1. Geographic extent check — Do your two layers cover the same spatial extent? If one covers all of Massachusetts and the other only Boston, you'll likely need to trim each layer down to the same study area.
Potential tools: Clip, Select by Location, Query
2. Projection check — Are your layers in the same coordinate system? Layers from different sources often aren't. In ArcGIS Pro, the map frame projects data on the fly based on the first layer loaded — if that first layer is already appropriately projected, others will usually display correctly without extra steps. Avoid permanently reprojecting a dataset as a routine fix; that changes the feature data itself.
Potential tool (only if truly needed): Reproject / Project
3. Attribute check — Is the attribute you actually need (e.g., income, price) already attached to the shapefile, or does it live in a separate table? If separate, you'll need to attach it using a shared ID field.
Potential tool: Join
Model Answer

Geographic extent check: Yes, this one applies. The Parcels layer already covers only the City of Boston, but the Census tract layer (and the ACS data joined to it) covers all of Suffolk County. You'll need to clip the tract layer down to Boston's city boundary so both layers cover the same study area.

Projection check: Census TIGER/Line layers and Analyze Boston layers may ship in different coordinate systems. If the first layer loaded in ArcGIS Pro is already in a projection appropriate for Massachusetts/Boston (e.g., NAD 1983 State Plane Massachusetts), the other layers will typically display correctly without any extra step. No need to permanently reproject the source data unless a specific analysis tool requires it.

Attribute check: Yes, this one applies to both datasets. The Property Assessment Excel/CSV must be joined to the Parcels shapefile using PID / GIS_ID. The ACS income table must be joined to the Census tract shapefile using GEOID. Neither comes pre-attached to its boundary layer — both need a join before you can map them.

Result — two maps: Since the two datasets don't need to share one geographic unit, you don't need to aggregate anything. Build Map 1: Boston parcels symbolized by assessed property value (after joining Property Assessment to Parcels). Build Map 2: Boston census tracts symbolized by median household income (after joining the ACS table to the clipped tract layer and joining it with GEOID). Viewing them side by side lets you start comparing where prices are high against where income is lower — the groundwork for the fuller analysis later in the semester.
